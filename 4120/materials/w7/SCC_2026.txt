 Basic idea
• Oracle-based algorithm:
• The oracle can always find a node in a sink SCC of 𝐺.
• Algorithm: Ask the oracle for a node 𝑢1 in some sink 𝑆𝐶𝐶 of 𝐺;
  run 𝐷𝐹𝑆(𝐺, 𝑢1 ) to find the nodes of this 𝑆𝐶𝐶 and extract them
  from 𝐺 to get the new graph 𝐺 ′ ; repeat this on 𝐺 ′ , etc, until the
  graph is empty.
• Example: Oracle gives node 𝐽 ∈ 𝐺𝐻𝐼𝐽𝐾𝐿, run DFS from 𝐽, find and
  take out 𝐺𝐻𝐼𝐽𝐾𝐿 from the graph. Next, in the new graph the
  oracle gives us node 𝐶 ∈ 𝐶𝐹, we take out 𝐶𝐹, etc.


• But we don’t have an oracle to help us. Ideas how to get nodes
  in sink SCCs?

 Basic idea
• Instead of the oracle: reverse the direction of the edges: sink
  SCCs become source SCCs!
    • Run a DFS to compute post values in the reversed graph.
      The highest post value is a node in a source SCC of the
      reversed graph ⇒ sink SCC of the original graph.
• Algorithm idea: Run DFS in the original graph to find the
  SCCs one by one by starting on nodes with the highest post
  value from the DFS on the reversed graph.
