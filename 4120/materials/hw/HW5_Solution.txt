Problem 1.
For each of the proposed hash functions given, determine whether they can be implemented and
used as actual hash functions for a hash table with N slots.

  (a) h(k) = 0

  (b) h(k) = random(0, N ) (where random(0, N ) gives a uniformly generated random number
      from 0 to N − 1).

  (c) h(k) = k mod N .

  (d) h(k) = k mod (N − 2) (Assume N ≥ 3).

  (e) h(k) = f (k) (where f (N ) is a deterministic function that runs in Θ(N 2 ) time and returns a
      value from 0 to N − 1).


Solution

Answers: a),c),d),e): Yes, b): No. Justification for e): Even though (a) will always result in
collisions, it is still a valid hash function. For (b), because the same input may not give the same
output has, it cannot be used as a valid hash function. For (e), it can be used as a hash function
even though it has a bad runtime as it satisfies the key idea of a hash function, that it maps arbitrary
key values to a fixed set of integers.

Problem 3.
Comparing open addressing to traditional chaining implementations it is true that under the same
loading factor:

    (a) In open addressing it takes on the average less time to do an unsuccessful search.
        Answer: Unsuccessful search takes 1/(1 − α) steps on the average whereas using chaining
        it takes a steps on the average. Since we require (because of open addressing) α < 1, open
        addressing is worse.

    (b) In open addressing insertions and deletions are faster.
        Answer: Since insertions take about the same time as unsuccessful searches, then open
        addressing must again be worse. Also deletions could be done in one step if we keep pointers.

    (c) In open addressing we save storage space since we don’t need pointers, so we can, for the
        same storage cost, build larger hash tables.
        Answer: True since we don’t keep pointers.

    (d) Collisions (i.e., that when we insert a key we don’t find an empty slot) are equally probable
        (under same loading factor, assuming the uniform hashing assumption)
        Answer: In open addressing all keys are in the hash table occupying a slot each; hence more
        slots are occupied on the average compared to the same keys inserted in a hash table with
        chaining (since in this later case more than one keys could be chained in the same slot).
        Then inserting a new item will find a busy slot with higher probability in the case of open
        addressing.
